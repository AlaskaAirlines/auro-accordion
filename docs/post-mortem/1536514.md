# Post-Mortem: Configurable trigger spacing via `variant="min"` (AB#1536514)

**Issue:** AB#1536514

## Reference documents
- Work item — [AB#1536514](https://dev.azure.com/itsals/E_Retain_Content/_workitems/edit/1536514)
- Fix PR — [#234](https://github.com/AlaskaAirlines/auro-accordion/pull/234)

## Summary

The Seats team needed a supported way to make the accordion more compact — specifically to
place a custom, arbitrarily-sized element in the trigger and have it sit flush against adjacent
content, without CSS hacks that reach into the component's shadow DOM. This shipped as the
**`variant="min"`** option on `auro-accordion` (propagated by `auro-accordion-group`), which removes all
trigger padding so the slotted trigger element controls its own size.

The change is self-contained in `auro-accordion` — **no `auro-button` change was required**, contrary
to the ticket's initial expectation (see below). The feature shipped cleanly, but two defects surfaced
during implementation that are worth recording: a shadow-DOM selector-scoping bug caught by tests, and
a design-token fallback bug in the demo caught by a user screenshot.

## Design evolution: `no-spacing` boolean → `variant="min"`

This capability was first built as a standalone reflected boolean attribute, `no-spacing`. It was later
folded into the existing `variant` attribute as the `min` value, so trigger sizing is now expressed
through a single scale — `variant` accepts `sm`, `lg`, and `min`, with the default (omitted) rendering the
medium trigger. Consolidating avoided a second, overlapping spacing API on the component. The mechanics
below are unchanged by the rename; the defects were found during the original `no-spacing` work and the
current identifiers (`variant="min"`, the `min` button class) are used throughout for accuracy.

## What landed

- `variant="min"` on `auro-accordion` (reflected `variant` attribute) and `auro-accordion-group`
  (reflected + propagated to children via `setAttribute("variant", …)` in `handleSlotContentChange()`,
  mirroring `emphasis`).
- SCSS zeroes trigger padding: the button block/inline padding via `:host(.min)` (`style-button.scss`) and
  the slotted trigger inline padding via `:host([variant="min"])` (`style.scss`).
- WTR tests: default-unchanged guard, all-sides-zero under `variant="min"`, property↔attribute reflection,
  group propagation.
- Docs: `min` documented alongside `sm`/`lg` in the "Variants" section of `docs/partials/api.md`, with
  `apiExamples/variant-min.html` and `apiExamples/variant-min-group.html`, including the presentational-only
  and accessible-name caveats.

## Cross-component claim (verified false)

The ticket stated trigger-spacing control "will likely require related work in `auro-button`." It does
not, for this scope. `src/styles/style-button.scss` already applies `all: unset` to `.auro-button` and
rebuilds its own padding, so `auro-accordion` fully owns the trigger's spacing. `auro-button` exposes no
spacing custom properties and locks its padding in its own shadow DOM; touching it would only be needed
for a *general* auro-button spacing API — a separate initiative. Verifying this up front kept the change
to one repo and avoided a needless cross-repo version/release coordination.

## Defect 1 — min styles targeted the wrong shadow root

**What broke.** The first implementation put the rule in `style-button.scss` keyed on a host *attribute*:

```scss
:host([no-spacing]) { .auro-button { padding: 0; } }
```

`style-button.scss` is the stylesheet for `auro-accordion-button` (the trigger), so its `:host` is the
**button** element. But the attribute is set on the **accordion**, not the button — so the selector never
matched and the button kept its 16px padding.

**Root cause.** Misplaced assumption that a host attribute on the outer component is visible to
`:host()` inside a nested child component's shadow root. It is not. The accordion communicates state to
its trigger button through two existing channels only: (a) classes added to the button in `render()`
(how `sm`/`lg` work), and (b) inherited CSS custom properties set on `.trigger` (how `emphasis` passes
`--trigger-padding-*`). The new rule used neither.

**Fix.** Mirror the `sm`/`lg` pattern — add a `min` class to the button in `auro-accordion.js`'s
`buttonClasses`, and key the child stylesheet on that class:

```js
// auro-accordion.js render()
min: this.getAttribute("variant") === "min",
```
```scss
// style-button.scss
:host(.min) { .auro-button { padding: 0; /* + trigger-padding vars */ } }
```

The slotted-trigger rule in `style.scss` is correct as an attribute selector because that stylesheet *is*
the accordion's own shadow root, so `:host([variant="min"])` matches there.

**How it was caught.** The "removes all trigger padding" WTR test asserted the *computed* padding on the
button (`expected '16px' to equal '0px'`) — not just attribute reflection. A reflection-only test would
have passed while the feature did nothing.

## Defect 2 — demo trigger rendered blank because a token overrode the fallback

**What broke.** An early demo example styled the trigger with
`background: var(--ds-color-container-primary-default, #0074c8)`. On the page the trigger rendered as a
blank white box (white background + white text), reported via a hover screenshot.

**Root cause.** `--ds-color-container-primary-default` is a **defined** Auro token that resolves to a
near-white container surface. A `var()` fallback is used only when the variable is *undefined* — since
the token exists, its white value won, and the `#0074c8` fallback was never applied.

**Fix.** Use a literal color in the demo (`background: #0074c8`) rather than relying on a token's
fallback. General lesson: a `var(--token, fallback)` does not mean "prefer fallback"; it means "use the
token if it exists at all." Verify a token actually resolves to the intended value instead of leaning on
the fallback. (The shipped `variant-min.html` example was later simplified to a plain text trigger, so this
custom-styled trigger no longer appears in the docs — the lesson still stands for any token-backed demo.)

## Verification

- **WTR** — 18 passed / 0 failed (`npm run test`), including the failing-first computed-padding test that
  exposed Defect 1.
- **Build** — `npm run build` succeeds; `docs/api.md` and the demo docs regenerate with the `variant="min"`
  option and the "Variants" examples.
- **Lint** — the change introduces **zero** new Biome errors. Remaining lint findings are pre-existing
  (untouched `apiExamples/toggle.js`, generated `iconVersion.js`, and pre-existing trailing-space JSDoc on
  other properties) and were intentionally left untouched to keep the diff focused.
- **Manual** — demo confirmed visually.

## What went right

- **Verified the cross-component assumption before coding.** Confirming `auro-button` did not need changes
  kept the blast radius to one repo.
- **Tested rendered effect, not reflection.** Asserting computed padding is exactly what surfaced Defect 1
  automatically instead of shipping a silent no-op.
- **Consolidated the spacing control into the existing `variant` scale** instead of shipping a second,
  overlapping boolean attribute.

## What went wrong

- **Assumed a nested component inherits the parent's host attribute for `:host()` matching.** It does not;
  state must cross the boundary via a class or an inherited custom property.
- **Relied on a design token's fallback in the demo without confirming the token's resolved value.**

## Recommendations

1. **When styling a nested child component from a parent state, use the established channel** (class in
   `render()`, or an inherited custom property) — never a `:host([attr])` selector in the child stylesheet
   keyed on an attribute that lives on the parent.
2. **Assert computed style / applied classes for any new visual attribute**, not just attribute reflection.
3. **Don't lean on `var(--token, fallback)` for demo/visual intent.** A defined token always wins; confirm
   the token resolves to the value you want, or use a literal.
4. **Follow-up (not this ticket):** if other teams want spacing control on bare `auro-button`, open a
   separate ticket for a general `auro-button` spacing API — this change deliberately did not touch it.
5. **Follow-up:** visual-regression coverage for `variant="min"` is still outstanding — this repo currently
   has no VRT tooling; baselines should be added wherever Auro's VRT runs.
